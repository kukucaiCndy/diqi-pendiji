## 4. 评审抓到的最有价值的几个问题（都已修）

这三个如果没被抓住，会在演示当天炸：

1. **`Color(0xB45309)` 只有 6 位十六进制 → alpha=0** —— 演示模式水印完全透明，AC-19 的「全屏水印」根本看不见。（lint 抓的）
2. **`REPLACE` 触发 `ON DELETE CASCADE`** —— 完成页回填自评时会静默删掉刚写的质量汇总行。（数据层评审 + sqlite3 复现）
3. **`stop()` 不冻结时间** —— 用户在第 3 次收缩时点结束，页面每 poll 一次 `completedReps` 就从 2 涨到 8，直接违反 AC-07「不补造整组」（训练引擎评审）

另外两个「防线本身是假的」：
4. 对比度自检页**度量了错误的底色** —— 心率值算的是白卡底 4.70，实际渲染在 canvas 上只有 4.34。等于专门用来证明 FR-15 的工具证明了另一个底色。
5. 免责文案的单测**只断言了测试自己写的字面量**，产品代码零覆盖。

三个「UI 是假的」：
6. 首页「点这里了解」**是假承诺** —— `onClick` 形参从未被引用，校准页整页不可达。
7. 感知状态三态实际只有两态，且把「演示模式」映射成「信号弱」是**编造状态**。
8. 无障碍描述被 `testTag` 门控 —— 有测试锚点的按钮才有描述，依赖方向反了。

## 5. 如实标注：本项目**没有**验证到的东西

这些不是"应该没问题"，是**确实没验**，验收时必须补：

| 项 | 原因 |
| --- | --- |
| **真实 FacePhys 指标链路全部未验证** | 工程里没有 AAR、没有 AppKey。桩是**故意永不返回数值**的，所以任何心率/呼吸率数字目前都出不来。AAR 到手后只需改 `sensor/FacePhysBridge.kt` 一个文件 + 1 行依赖 |
| **AC-10 TalkBack 运行时流程** | 本机**没有 TalkBack 包**。只验证到 Compose 语义节点带描述 |
| **AC-03 真实飞行模式** | adb 走 WiFi，开飞行模式会切断自己的调试通道。目前只能用 `svc data disable` + 静态审计代理 |
| **AC-06 真实来电** | 真机无 `cmd telecom` 注入通道。目前只有音频焦点纯函数测试 + 结构保证 |
| **AC-16/17 物理遮脸与强光** | 逻辑路径可用故障注入覆盖，物理部分需人配合 |
| **ML Kit 在无 GMS 设备上的行为** | 本机有 GMS，测不出差异。模型确认随包，但需一台无 GMS 设备补验 |
| **需求 §7 性能/功耗硬指标**（掉帧<5%、耗电≤10%、温升） | 未做，排在 S9 |
| **语音内容与文案一一对应** | 只能验证素材存在且非空，无法验证 `contract.m4a` 里念的确实是收缩文案 |
| **Room 迁移** | schema 已导出，但只有 v1，没有迁移测试 |

另有一条**测量方法**的坑记一下：`uiautomator dump` 把带 testTag 的节点报成 `clickable=true` 且 `content-desc` 为空，朗读文本落在合并子节点上——按 dump 统计会得到"6 个可点节点全缺描述"的假阴性。AC-10 的判据已改到 Compose 语义层。
