## 2. 当前**阻挡目标完成**的三件事（需要你）

### 2.1 设备掉线（自第 10 轮起，已连续 5 轮）

```
adb connect 192.168.1.26:41015  →  Connection refused
adb devices                     →  空
```

判断是**无线调试服务已停止监听**。两种可能原因：
1. 设备重启（Android 的无线调试重启后不会自动恢复）；
2. **我的自动化点击误触了系统通知「点按即可关闭无线调试功能」** —— 脚本大量用坐标点击，
   这是我引入的真实风险，已在 `docs/PROGRESS.md` 记录。

**恢复操作**：`设置 → 开发者选项 → 无线调试 → 开启`，确认端口仍是 `41015`。
若是新端口，告诉我新端口即可。

> 影响：仪器化测试（32 项）、E2E 截图、`gfxinfo` 性能测量全部停摆。

### 2.2 FacePhys SDK（挡住真实心率/呼吸率）

从未收到 **AAR + AppKey + 加密模型 `.enc`**。

现在 `facephys-api` 是**契约桩**：帧链路（CameraX → ML Kit 人脸 → 9×9×3 ROI → 投喂）
真实运行，最后一环如实返回 `MODEL_MISSING`，**绝不出假数**。
P03 校准页的诊断区会直接显示 `STUB-0.0.0-contract`，一眼可辨。

**拿到后要做的**：替换 `facephys-api` 的依赖 + 把 `.enc` 放进 `app/src/main/assets/`，
然后 `FacePhysBridge` 就会出真实 `MetricsRead`。预计 1 天内可验证 AC-15/16/17 的真实数值侧。

### 2.3 TalkBack（挡住 AC-10）

## 4. 唯一未达标的**非功能**指标：掉帧

| 阶段 | p90 | 掉帧比例 |
| --- | --- | --- |
| 原始（100ms 无条件推帧） | 34ms（543 帧） | 35.5% |
| 按显示签名去重（1 秒/次） | 61ms | 52.5% |
| + 拆状态流 + `PhaseTimeline` 收原语 | 48ms | 55% |
| + `LazyColumn` 按 item 增量测量 | 48ms | 54.8% |
| + 去掉重复的 36sp 倒计时 | **未测**（设备掉线） | — |

需求是 **< 5%**。已归因清楚：运行中每秒一帧、每帧约 48ms；暂停后 **0 帧 0 慢**，
所以是"单次重组太重"，不是帧率不足。

**剩余两步（已定位，未做）**：
1. 圆环改 `Modifier.drawBehind`，把文字移出 Canvas（只重绘弧线，不重排版文字）；
2. 必要时倒计时自绘（`TextMeasurer` 预测量 + 缓存）。

## 5. 需要产品/临床裁定的 6 件事

1. **演示模式的"全屏水印"**：FR-14 原文要求全屏水印，现在实际是**指标卡内一枚 chip**
   （`P04_DEMO_WATERMARK`，有测试）。接受 chip 就改判据，否则要加水印层。
2. **关闭演示模式是否删除演示记录**：现在会删（`deleteSimulated()`），
   与 FR-14「记录页以水印样式展示」冲突。统计侧已有 SQL 过滤，不删也不会污染。
3. **训练参数默认值**（收缩/保持/放松各 5s、8 次）需临床签字。`planVersion` 已隔离，调参不破坏历史。
4. **SQI 门限 0.50** 需真机标定。
5. **「清除数据」语义**：现在清业务数据、保留同意与筛查留痕（合规优先）。
6. **语音是 macOS 合成音**：正式版是否换真人录音（`VoiceScript` 单一来源，换只换 assets）。
