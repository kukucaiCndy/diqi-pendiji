## 1. 为什么要合并

旧信息架构（需求 §5.1 原文）：底部 4 Tab —— 首页 / 训练 / 记录 / 我的。

实际实现后发现一个结构性重复：

- **首页**上就有「今日训练卡 + 开始按钮」，是真正的训练入口；
- **训练** Tab 却指向一个「准备开始」页，而准备页的主按钮又跳去训练页。

也就是说 **两个 Tab 都在做"开始训练"这件事**，用户要在两页之间判断"该点哪个"。
对 55+ 用户，这是纯噪音。

**决定：合并为一个「训练」Tab，底栏变为 3 个 —— 训练 / 记录 / 我的。**

代价（如实记录）：
- 需求 §5.1「底部 4 Tab」被主动变更，验收时需产品确认；
- 「准备开始」页作为独立页面取消，其内容（语音引导词、就医提示）已并入训练 Tab。

## 2. 摄像头：可选，且必须"看得见地可选"

需求 FR-03 写「摄像头校准（可选入口，可跳过）」，FR-15 与 AC-04 也围绕"不开摄像头也能练"。
但**"可选"不能靠藏起来实现**。旧实现把真正入口埋在准备页的一个小 chip 里
（「开启摄像头（可选）」），主按钮则直接进训练 —— 用户根本不知道还有另一条路。

### 2.1 两条路径都放在今日训练卡上

```
┌─ 今日训练卡（深色 #0F1A24）───────────────────┐
│  今日训练                                     │
│  8 次 · 约 3 分钟                             │
│  准备 5s / 收缩 5s / 保持 5s / 放松 5s         │
│                                               │
│  ┌─────────────────────────────────────────┐ │
│  │ ▶  开启摄像头训练        ← 主按钮（薄荷绿）│ │
│  └─────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────┐ │
│  │     不用摄像头，直接训练  ← 次按钮（描边） │ │
│  └─────────────────────────────────────────┘ │
└───────────────────────────────────────────────┘
```

| 选项 | 视觉权重 | 去向 |
| --- | --- | --- |
| **开启摄像头训练** | 主按钮：`#5EEAD4` 实心 + 播放图标 + 17sp/700 `#062530` | P03 校准 → 就绪后「开始训练」带 `camera=true` 进训练 |
| **不用摄像头，直接训练** | 次按钮：透明底 + `#34495E` 描边 + 16sp/600 `#8FA3B8` | 直接进训练，`camera=false` |

**为什么不做成"主按钮 → 弹窗里再选"**：那是把一次选择拆成两次点击。
对目标用户，弹窗是额外的认知负担，而且会让"主路径"看起来像唯一的路径。

**为什么次按钮不用红/灰禁用态**：它不是"危险/次要到可以忽略"，而是**同等合法**的选择，
只是不叠加感知能力。所以用"描边次级"而不是"弱化到看不见"。

### 2.2 状态行不再催促

旧文案「训练前需开启摄像头 · 去开启」在旧 IA 下说得通（摄像头是主路径）。
新 IA 下它与下面的「不用摄像头，直接训练」**直接矛盾**，会让人以为必须先开摄像头。

改为陈述当前状态：

| 状态 | 文案 | 行为 |
| --- | --- | --- |
| 未开启 | 「摄像头未开启 · 不影响练习」 | 可点 → 进校准页（不催促） |
| 已就绪 | 「摄像头已就绪」 | 无动作 |
| 信号弱 | 「信号偏弱 · 可点这里调整」 | 可点 → 进校准页 |

### 2.3 路由参数

`training/live?camera={true|false}` —— 选择由用户在主按钮上做出，作为导航参数带进训练页，
`TrainingViewModel(cameraEnabled = ...)` → `TrainingDeps.sensorFor(demoMode, cameraEnabled)`。

**当前限制（必须说清）**：FacePhys SDK 未接入，`sensorFor` 对
`cameraEnabled` 的两种取值都返回空源。因此即使选了"开启摄像头训练"，
训练页指标区仍如实显示「未开启感知」—— **不会因为开了摄像头就伪造数据**。
等 AAR 到位后，这里只需让 `cameraEnabled=true` 分支返回 `RppgSensor`。

### 过程中修掉的一个真 bug

`CALIBRATE` 的两个回调原本都是 `popBackStack()` —— 合并 IA 之后，
点「开始训练」会退回训练 Tab 而**不是**进训练页。已改成显式 `navigate`。

## 5. 需要产品确认

1. 需求 §5.1「底部 4 Tab」正式变更为 **3 Tab**。
2. 「准备开始」页取消，其内容并入训练 Tab —— 若坚持保留独立准备页，需重新设计它的定位。
3. 摄像头选项的**默认高亮**：目前主按钮是"开启摄像头"（推理：数据更完整）。
   若产品希望"默认不用摄像头"以免用户被权限弹窗劝退，需要把两个按钮的主次对调 —— 这是产品判断，不是技术判断。
